# DatePicker 💖

Маленький веб-сюрприз: сайт-приглашение на свидание с шуточной убегающей кнопкой
"Нет", выбором активности/ресторана/даты, экспортом в календарь и уведомлением
тебе в Telegram. Управление контентом — через защищённую админ-панель.

Стек: **FastAPI + PostgreSQL + React (Vite + TypeScript) + Tailwind**,
обёрнут в Docker Compose и опубликован под **Caddy** (автоматический HTTPS).

---

## Возможности

### Для девушки
- 💞 Старт: "Пойдёшь со мной на свидание?" — кнопка "Нет" убегает от курсора
  на десктопе и **телепортируется в случайное место** при любой попытке
  тапнуть на мобильном. Нажать её невозможно.
- 🗺️ Выбор активности из списка (заполняешь в админке): название, описание,
  опциональная ссылка (Яндекс.Карты, 2ГИС…), картинка.
- 🍽️ Опционально шаг "где поедим" — глобально или per-activity
  (для каждой активности можно ограничить список ресторанов или вовсе
  пропустить этот шаг).
- 🗓️ Выбор даты:
  - Из заранее предложенных тобой вариантов
  - Или свой вариант (если разрешено)
  - Только будущие даты (если включено)
  - Длительность встречи
- ✅ Сводный экран с возможностью **подтвердить или изменить**.
- 🎉 Конфетти после подтверждения.
- 📅 Экспорт в календарь:
  - **`.ics` файл** — открывается в Apple Calendar (iPhone), Outlook,
    Google Calendar и т.д. На iOS открытие `.ics` ссылки предлагает
    "Добавить событие" прямо из приложения "Календарь".
  - **Google Calendar** — ссылка `calendar.google.com/render`,
    предзаполняющая событие.
- 🌐 Переключение языка (RU / EN).
- 🎨 Переключение темы: романтичная (розовая с сердечками) или минималистичная
  (светлая / тёмная).

### Для тебя (админ)
- 🔐 Авторизация по логину/паролю (bcrypt + подписанная сессионная cookie,
  `HttpOnly`, `SameSite=Lax`, `Secure` под HTTPS).
- 📛 Управление приглашениями: создание под имя ("Лена", "Маша" 🙃),
  отзыв (`rotate token`), деактивация, удаление, копирование ссылки.
  Каждая девушка получает **уникальную секретную ссылку** с UUID-токеном.
- 🧩 Управление активностями и ресторанами: имя, описание, ссылка,
  картинка (загрузить файл **или** вытянуть OG-изображение со ссылки),
  сортировка, активность.
- 🔗 Для каждой активности — настройка "разрешённых ресторанов":
  все / выбор из списка / пропустить шаг ресторана.
- 🕒 Управление слотами дат — это твои предложения, которые увидит девушка.
- ⚙️ Настройки: язык/тема по умолчанию, что разрешать переключать,
  включать ли шаг ресторана глобально, разрешать свою дату, требовать
  будущую дату, разрешать перевыбор, конфетти.
- 📜 История свиданий и **аудит-лог**: открытие ссылки, нажатия "Да",
  попытки нажать "Нет", смена шагов, экспорт в календарь, отправка.

### Уведомления
- 📨 **Telegram-бот** (через `@BotFather`): мгновенное сообщение с деталями.
- 🔔 **Webhook** (Discord/Slack/свой): POST JSON `{content, text}` —
  совместимо с Discord и Slack webhooks из коробки.

### Безопасность
- 🔒 HTTPS из коробки (Caddy + Let's Encrypt).
- 🪪 Сессионные cookie подписаны `itsdangerous` (HMAC), не JWT, не localStorage.
- 🧂 Пароли админа — bcrypt.
- 🚦 Rate limit (SlowAPI): глобальный 120/мин, на `/auth/login` 10/мин,
  на сабмит 10/мин.
- 🛡️ Strict security-заголовки в Caddy (HSTS, CSP, X-Frame-Options, …).
- 🧱 OG-скрапер защищён от SSRF: запрещает приватные/loopback хосты,
  ограничивает редиректы и размер ответа.
- 🖼️ Загружаемые картинки проверяются Pillow + ограничение типа/размера,
  имя файла генерируется на сервере — никаких path traversal.
- 🪧 `<meta name="robots" content="noindex, nofollow">` на странице приглашения.
- 🔁 Аудит-лог пишется только в allow-list событий и обрезается по размеру.

## Архитектура

```
┌──────────────┐  HTTPS  ┌──────────────┐
│   Caddy      │ ◀────── │   Browser    │
│ (TLS, HSTS,  │         └──────────────┘
│  CSP, gzip)  │
└──────┬───────┘
       │
       ├──► /api/*    → FastAPI (Python) ─► PostgreSQL
       ├──► /media/*  → FastAPI (uploaded images)
       └──► /*        → Nginx со статикой React-сборки
```

- `backend/` — FastAPI + SQLAlchemy 2 + автосоздание таблиц при старте.
- `frontend/` — Vite + React + TypeScript + Tailwind, отдаётся через Nginx.
- `caddy/Caddyfile` — TLS-терминация, security headers, проксирование.
- `data/uploads/` — папка с пользовательскими изображениями, проброшена
  как volume в backend.

## Запуск

### 1) Подготовка `.env`

```bash
cp .env.example .env
```

Открой `.env` и **обязательно**:

1. Сгенерируй `SECRET_KEY`:
   ```bash
   python3 -c "import secrets; print(secrets.token_urlsafe(64))"
   ```
2. Поменяй `POSTGRES_PASSWORD` и `ADMIN_PASSWORD` на крепкие.
3. Поставь `PUBLIC_BASE_URL` равным тому, по чему сайт будет открываться
   снаружи (например, `https://date.example.com`). Это URL используется
   для генерации ссылок-приглашений и `UID` в `.ics` событиях.
4. Если хочешь Telegram-уведомления:
   - Создай бота через [@BotFather](https://t.me/BotFather), получи `TOKEN`.
   - Напиши боту что-нибудь, открой
     `https://api.telegram.org/bot<TOKEN>/getUpdates` — увидишь свой `chat.id`.
   - Заполни `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
5. Опционально — Discord/Slack webhook в `NOTIFY_WEBHOOK_URL`.
6. `DOMAIN` — для **продакшена** реальный домен (Caddy сам получит сертификат),
   для **локалки** — `localhost` (Caddy выпустит self-signed внутренний TLS).
   `ACME_EMAIL` — твой email для Let's Encrypt (только для прод).

### 2) Запуск

```bash
docker compose up -d --build
```

Открой:
- `https://<DOMAIN>/admin` — админка (логин из `.env`),
- `https://<DOMAIN>/i/<token>` — ссылка-приглашение
  (увидишь её в админке после создания приглашения, а первое
  предустановленное создаётся автоматически при первом старте).

### 3) Локальная разработка (без Docker)

Бэк:
```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export DATABASE_URL=postgresql+psycopg://datepicker:pass@localhost:5432/datepicker
export SECRET_KEY=$(python3 -c "import secrets;print(secrets.token_urlsafe(64))")
export ADMIN_USERNAME=admin ADMIN_PASSWORD=admin
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Фронт:
```bash
cd frontend
npm install
npm run dev
```

Vite сам проксирует `/api/*` и `/media/*` на `http://localhost:8000`.

## Особенности и заметки

- **iPhone и `.ics`**: на iOS клик по ссылке `.ics` открывает
  предпросмотр события и предлагает "Добавить в календарь". Это
  работает прямо из Safari без отдельной интеграции.
- **Google Calendar**: используется ссылка `calendar.google.com/render`
  с предзаполненными полями — это удобнее, чем требовать у пользовательницы
  пройти OAuth каждый раз. Если захочешь полноценную OAuth-интеграцию —
  заведи проект в Google Cloud Console и добавь scope
  `https://www.googleapis.com/auth/calendar.events`.
- **Яндекс.Карты**: используется парсинг OG/Twitter-тегов
  (`og:image`, `twitter:image`). У Яндекс.Карт превью обычно есть, но
  у конкретных мест может не быть фото — в таком случае
  кнопка "Pull image" покажет "No image found", и ты сможешь загрузить файл
  вручную.
- **Поведение убегающей кнопки** — десктоп: убегает при курсоре в радиусе
  120px; мобайл: телепорт в случайное место на любой touchstart/focus/click.
  Нажать её невозможно.
- **Перевыбор**: в настройках есть `allow_resubmit`. Когда выключен — после
  первого сабмита девушке показывается экран "Мы уже договорились" с
  деталями свидания и кнопками экспорта.
- **Несколько приглашений**: можно создавать сколько угодно приглашений.
  У каждой — своя ссылка, своя история, своя аналитика в аудит-логе.

## Что хранится в Docker volume

- `db_data` — данные PostgreSQL.
- `uploads` — загруженные картинки активностей/ресторанов.
- `caddy_data` / `caddy_config` — сертификаты Let's Encrypt и состояние Caddy.

Бэкап:
```bash
docker compose exec db pg_dump -U $POSTGRES_USER $POSTGRES_DB > backup.sql
```
